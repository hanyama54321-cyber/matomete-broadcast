# 周知 一括投稿ツール(matomete-broadcast)

3社(HI-LINE・A-LOGI・名豊興運)の「周知・おしらせ」に、同じお知らせを1回の操作で投稿するローカル用のツールです。
中身は「各社アプリの『投稿する』ボタンと同じ書き込みを、3社分まとめて行う」だけで、3社の Firebase 同士はつなぎません。

- 版: 0.1.0(2026-10-18)
- 使う端末: 南野さんのマイPCだけ。GitHub Pages では公開しない。会社PCでは使わない
- 必要なもの: Node.js(このPCには入っている)と、インターネット接続

## できること・できないこと

| できる | できない(各社アプリで行う) |
|---|---|
| 新規・即時公開のお知らせを、1〜3社へ同時に投稿 | 編集・削除・予約(下書き)・未読リマインダー |
| タイトル・本文の `{会社名}` を各社名に差し込む | 社ごとに本文を書き分ける(差し込みは `{会社名}` だけ) |
| 結果を文字でコピー(Notion への記録用) | 投稿履歴の保存 |

## 起動

1. `start-broadcast.bat` をダブルクリックする
2. ブラウザで `http://localhost:8765/broadcast.html` が開く(開かなければ、このアドレスを手で開く)
3. 使い終わったら黒い画面を閉じる(または Ctrl+C)

- `broadcast.html` をファイルとして直接開いたとき(`file://`)や、`localhost` 以外の場所で開いたときは、Firebase に接続せず、ログイン欄・入力欄・送信ボタンも出ません(案内の文だけが出る)。ログインも送信もできません
- 簡易サーバー(`serve.js`)は `broadcast.html` だけを返し、このPCの中からしか接続できません

## 使い方

### 1. 各社にログイン

- 会社ごとに、メンテ用の管理者コード **BBBBB か CCCCC** とパスワードでログインします。各社の欄に projectId が出るので、取り違えていないか確かめてください
- パスワードはどこにも保存しません(ブラウザが保存を提案しても保存しないでください)。コードだけは次回のために記憶します
- タブを閉じると3社ともログアウトします
- 次の場合はその社に投稿できません(理由が表示されます)
  - コードが `AAAAA`(外部に開示済みのため)
  - 入力したパスワードがコードと同じ = 初期パスワードのまま(大文字・小文字の違いだけのものも止めます)
  - `users/{コード}` が無い、または `role` が `admin` でない
- ログインした人の `users.name` が空のときは、下の「投稿者名」を入力しないとその社には送れません

### 2. 内容を書く

- タイトル・本文・カテゴリ・タグ・優先度・必読・既読期限・上部に固定。並び・既定値・選択肢は各社アプリの「新しいお知らせ」と同じです
- タイトル・本文の `{会社名}` は、`HI-LINE` / `A-LOGI` / `名豊興運` に置き換わります(「{会社名} を差し込む」ボタンでも入れられます)
- **投稿者名**: 空欄なら各社でログインした人の名前(アプリと同じ動き)。入力すると3社ともその名前になります。`authorUid` はいつもログインしたコードです

### 3. プレビューと送信先

- 3社の仕上がりが並びます(枠の色: HI-LINE=青、A-LOGI=赤、名豊興運=紺)
- 社ごとに「送る」のON/OFFを選べます。ログインしていない社・投稿できない社はOFFのまま変えられません
- **タイトル・本文・タグに `<` `>` `&` を含むと、HI-LINE には送れません。** HI-LINE 0.4.8 はお知らせを HTML のまま表示するため、表示が崩れるからです(HI-LINE 側の表示修正が入るまでの暫定措置)

### 4. 確認して送信

- 「確認へ」で確認画面が出ます。社ごとにタイトル・投稿者名・カテゴリ・必読の有無が並び、必読のときはロック画面に出る文言(`📌 必読: タイトル`、タイトルは60文字で切れる)と、通知を許可している人数の概算が出ます
- 人数が取れなくても送信はできます(取れなかったことは表示されます)
- **送信後は取り消せません。** キャンセルすると、どの社にも書き込みません

### 5. 結果と再送

- 社ごとに「成功 / 失敗(理由) / 対象外(理由)」と、ドキュメントID が出ます
- **失敗した社だけ「同じIDで再送」できます**(成功した社は押せません)。同じIDのお知らせが既にあれば何も書き込まないので、二重投稿にも、必読通知の二重送信にもなりません
- 「結果をコピー」で記録用の文字をコピーできます
- 送信後は入力欄が固定されます。次のお知らせは「新しいお知らせを作る」から(入力と結果が消えるので、先にコピーしておく)

## 書き込む内容

各社アプリの `submitAnnPayload()` の「新規・即時公開」と同じ16項目だけを書きます(項目は増やさない)。

| 項目 | 値 |
|---|---|
| `title` / `body` | 前後の空白を除き、`{会社名}` を差し込んだ文字列 |
| `category` | `safety` / `work` / `hr` / `system` / `other` |
| `priority` | `high` / `normal` / `low` |
| `target` | `'all'` |
| `pinned` / `mustRead` | 真偽値 |
| `readDeadline` | `'YYYY-MM-DD HH:MM'` か `null` |
| `tags` | 文字列の配列(20文字以内・最大5個・重複なし・先頭の `#` を外す) |
| `status` | `'published'` |
| `scheduledAt` | `null` |
| `updatedAt` / `createdAt` / `publishedAt` | サーバー時刻 |
| `authorUid` | ログインしたコード |
| `authorName` | 投稿者名(空欄ならログインした人の `users.name`) |

- ドキュメントID は1回の一括送信につき1つ(例: `bc-20261017-2004-k3f9`)で、3社で同じIDを使います
- 書き込みは「無ければ作る」だけです。先にサーバーから読み、無いときだけトランザクションで作成します。既にあるドキュメントは上書きしません(上書きすると `notifiedAt` が消え、必読通知がもう一度全員に飛ぶため)
- 社ごとに順番に書き込み、1社が失敗しても他社は止めません

## 通知について

- 必読ONのときのプッシュ通知は、各社のサーバー処理 `onAnnouncementNotify` がこれまでどおり送ります。ツールから通知は送りません
- 必読OFFでもプッシュ通知は飛びませんが、ベル・タブの赤い点は全員に付きます

## 本番での初回確認(南野さんが行う)

1. 3社にログインし、必読ONのお知らせで確認画面に人数が出るところまで進めて、**キャンセル**する(送信しない)
2. 実際の投稿の初回は、**必読OFF**の短いお知らせを、**乗務員への案内前の社1社だけ**に送る(ほかの2社は「送る」をOFF)→ その社のアプリで表示を確認 → アプリから削除
   - 必読OFFでもプッシュ通知は飛ばないが、ベル・タブの赤い点は全員に付く
3. 3社同時の初回は、実際に出したいお知らせで行う

## 申し送り(各社アプリ側を変えたとき)

このツールは、各社アプリの次の部分を写して作っています。アプリ側を変えたら、ツールも合わせて直してください(`broadcast.html` の該当箇所にもコメントがあります)。

- 各社 `index.html` 冒頭の `firebaseConfig`(→ `COMPANIES`)。projectId・authDomain・Functions のリージョンを変えたら、`broadcast.html` の `<head>` にある Content-Security-Policy の宛先(`connect-src`・`frame-src`)も直す
- ログイン方式 `AUTH_EMAIL_DOMAIN` / `AUTH_PW_SUFFIX`
- エディタのカテゴリ(`annCategories`)・優先度・既定値・タグの正規化(`addEdTagFromInput()`)
- 投稿の項目(`saveAnn()` / `submitAnnPayload()` → `PAYLOAD_KEYS`・`buildPayload()`・`checkPayload()`)
- `announcements` のルール、`onAnnouncementNotify`(タイトルを60文字で切る)、`firebase-messaging-sw.js` の通知文言、`estimateNotifyAudience` の呼び方
- HI-LINE がお知らせを文字として表示するよう直ったら、`COMPANIES` の HI-LINE の `rendersHtml` を `false` にする(`< > &` の暫定措置が外れる)

## エミュレーターでの確認(本番には触れない)

アプリやツールを変えたときに、3社のエミュレーター(各社の `firestore.rules` と `functions` を読み込む)で確かめるための道具が `emulator/` にあります。作業用のファイルは Google ドライブの外(既定: `%LOCALAPPDATA%\matomete-broadcast-emu`)に作ります。

```
node emulator/prepare.js --repos <3社のリポジトリを並べたフォルダ>   (初回・各社を更新したとき)
node emulator/start.js                                                (3社のエミュレーターを起動。別の画面で動かしたままにする)
node emulator/seed.js                                                 (検証用アカウントを作り直す)
node serve.js                                                         (ツールの簡易サーバー)
```

- ツールは `http://localhost:8765/broadcast.html?emulator=1` で開くとエミュレーターに接続します(画面上部にオレンジの帯が出る)
- 各社アプリの写し(エミュレーター接続版)は `http://localhost:8766/hiline/index.html`(`alogi` / `meiho` も同様)。比較用の投稿をアプリから作れます
- 検証用アカウント(コード・パスワード)は `emulator/config.js` の `TEST_USERS`。エミュレーターの中にだけあり、本番とは無関係です
- 中身の確認: `node emulator/inspect.js list`(一覧)/ `compare <key> <idA> <idB>`(項目名・型の比較)/ `fnlog`(`onAnnouncementNotify` の実行回数)/ `tokens`
- 確認画面の人数を見るときは `node emulator/seed.js --tokens` で架空の通知トークンを入れる。**必読の送信を試す前に必ず `--clear-tokens` で消す**(トークンがあると functions が本物の FCM に送ろうとするため)

## ファイル

| ファイル | 内容 |
|---|---|
| `broadcast.html` | ツール本体(1枚) |
| `serve.js` | このPCの中だけで開くための簡易サーバー(依存パッケージなし) |
| `start-broadcast.bat` | 起動用(`serve.js` を起動してブラウザを開く) |
| `emulator/` | エミュレーターでの確認用の道具 |

外部から読み込むのは gstatic の Firebase JS SDK(compat 10.14.1。各社アプリと同じ版)だけです。内容が書き換えられていたら読み込まないよう integrity を付けています。

通信できる宛先は、SDK のコードで確かめた次のものだけに絞っています(`broadcast.html` の Content-Security-Policy)。

| 宛先 | 用途 |
|---|---|
| `identitytoolkit.googleapis.com` | ログイン |
| `securetoken.googleapis.com` | ログインの更新 |
| `firestore.googleapis.com` | Firestore の読み書き |
| `asia-northeast1-anzen-matomete-app.cloudfunctions.net` ほか2社分 | 人数の概算(`estimateNotifyAudience`) |
| `127.0.0.1` / `localhost` | 検証用のエミュレーター |
