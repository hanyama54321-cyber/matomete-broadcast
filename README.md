# 周知 一括投稿ツール(matomete-broadcast)

3社(HI-LINE・A-LOGI・名豊興運)の「周知・おしらせ」に、同じお知らせを1回の操作で投稿するツールです。
中身は「各社アプリの『投稿する』ボタンと同じ書き込みを、3社分まとめて行う」だけで、3社の Firebase 同士はつなぎません。

- 版: 0.3.0(2026-10-20。0.1.0 はマイPCだけで使う版、0.2.0 から GitHub Pages でも公開、0.2.1 で管理者コードを画面に出さないようにし、`{会社名}` の置き換えを「CB名古屋」を入れるボタンに替えた。0.2.2 で初期パスワードのままでもログインできるようにした。0.3.0 で「送ったお知らせ」タブ(既読状況・未読リマインド)を加えた。0.4.0(2026-10-21)で、一括送信したお知らせの訂正・削除を加えた)
- 使う端末: 南野さんのマイPC(`start-broadcast.bat` で開く)と、会社ネットワーク外のPC(公開URLで開く)。会社PCでは使わない
- 公開URL: https://hanyama54321-cyber.github.io/matomete-broadcast/
- 必要なもの: インターネット接続。マイPCで `start-broadcast.bat` を使うときは Node.js も(マイPCには入っている)

## できること・できないこと

| できる | できない(各社アプリで行う) |
|---|---|
| 新規・即時公開のお知らせを、1〜3社へ同時に投稿 | 予約(下書き) |
| 「CB名古屋」をボタン1つで入れる(入れるかどうかはその都度決める) | 社ごとに本文を書き分ける(3社とも同じ文字で送る) |
| 結果を文字でコピー(Notion への記録用) | 投稿履歴の保存 |
| 一括送信したお知らせの既読状況を3社並べて見る(0.3.0) | アプリから個別に投稿したお知らせの既読状況(各社アプリで見る) |
| 一括送信したお知らせの未読の人に、社ごとにリマインドを送る(0.3.0) | 自動で何度もリマインドする |
| 一括送信したお知らせを、社ごとに選んで訂正・削除する(0.4.0) | アプリから個別に投稿したお知らせの編集・削除、必読の ON/OFF・投稿者の変更 |

## 開き方

動くのは次の2つの場所だけです。

| 使う端末 | 開き方 |
|---|---|
| マイPC | `start-broadcast.bat` をダブルクリックすると `http://localhost:8765/` が開く(開かなければ手で開く)。使い終わったら黒い画面を閉じる(または Ctrl+C) |
| 会社ネットワーク外のPC | 公開URL https://hanyama54321-cyber.github.io/matomete-broadcast/ を開く |

- それ以外の開き方では、Firebase に接続せず、ログイン欄・入力欄・送信ボタンも出ません(案内の文だけが出る)。ログインも送信もできません。たとえば `index.html` をファイルとして直接開いたとき(`file://`)、`localhost` の別のポート、`github.io` のほかのパスに置いた写し、ほかのページの中に埋め込まれたとき
- エミュレーター接続(`?emulator=1`)は `localhost:8765` のときだけ使えます。公開URLに `?emulator` を付けると締め出されます
- 簡易サーバー(`serve.js`)はツール本体(`index.html`)だけを `/` で返し、このPCの中からしか接続できません。0.1.0 までの `http://localhost:8765/broadcast.html` は、`?emulator=1` などを保ったまま `/` に移ります
- 0.2.0 からツール本体は `index.html` です(0.1.0 までの `broadcast.html` は無くなりました)。公開URLの直下で本体を直接開くため、`?emulator` が付いていれば必ず締め出せます
- 公開URLで使い終わったら、タブを閉じてください(ログインはタブを閉じると消えます)

## 使い方

### 1. 各社にログイン

- 会社ごとに、メンテ用の管理者コードとパスワードでログインします(どのコードを使うかは南野さんが管理し、画面や README には書かない)。各社の欄に projectId が出るので、取り違えていないか確かめてください
- パスワードはどこにも保存しません(ブラウザが保存を提案しても保存しないでください)。コードだけは次回のために記憶します
- タブを閉じると3社ともログアウトします
- 次の場合はその社に投稿できません(理由が表示されます)
  - 外部に開示済みのメンテ用コード(画面には「このコードはこのツールでは使えません」とだけ出る)
  - `users/{コード}` が無い、または `role` が `admin` でない
- 初期パスワード(コードと同じ)のままのアカウントでもログイン・送信はできます。その社の欄に「初期パスワードのままです」と注意が1行出ます(0.2.2 で、リスクを承知のうえで止めないことにした。0.2.1 までは止めていた)
- ログインした人の `users.name` が空のときは、下の「投稿者名」を入力しないとその社には送れません

### 2. 内容を書く

- タイトル・本文・カテゴリ・タグ・優先度・必読・既読期限・上部に固定。並び・既定値・選択肢は各社アプリの「新しいお知らせ」と同じです
- 「CB名古屋 を差し込む」を押すと、タイトルか本文のカーソルの位置に「CB名古屋」と入ります。入力した文字は、3社ともそのまま送ります(0.2.0 までの `{会社名}` の置き換えは 0.2.1 でやめました。残っていると警告が出ます)
- **投稿者名**: 空欄なら各社でログインした人の名前(アプリと同じ動き)。入力すると3社ともその名前になります。`authorUid` はいつもログインしたコードです

### 3. プレビューと送信先

- 3社の仕上がりが並びます(枠の色: HI-LINE=青、A-LOGI=赤、名豊興運=紺)
- 社ごとに「送る」のON/OFFを選べます。ログインしていない社・投稿できない社はOFFのまま変えられません
- `<` `>` `&` を含むお知らせも、3社とも送れます。HI-LINE は 0.4.8 までお知らせを HTML のまま表示していたため送信先から外していましたが、0.4.9(main `7342e93`)で文字として表示するよう直ったので、2026-10-19 にこの暫定措置を解除しました

### 4. 確認して送信

- 「確認へ」で確認画面が出ます。社ごとにタイトル・投稿者名・カテゴリ・必読の有無が並び、必読のときはロック画面に出る文言(`📌 必読: タイトル`、タイトルは60文字で切れる)と、通知を許可している人数の概算が出ます
- 人数が取れなくても送信はできます(取れなかったことは表示されます)
- **送信後は取り消せません。** キャンセルすると、どの社にも書き込みません

### 5. 結果と再送

- 社ごとに「成功 / 失敗(理由) / 対象外(理由)」と、ドキュメントID が出ます
- **失敗した社だけ「同じIDで再送」できます**(成功した社は押せません)。同じIDのお知らせが既にあれば何も書き込まないので、二重投稿にも、必読通知の二重送信にもなりません
- 「結果をコピー」で記録用の文字をコピーできます
- 送信後は入力欄が固定されます。次のお知らせは「新しいお知らせを作る」から(入力と結果が消えるので、先にコピーしておく)

### 6. 送ったお知らせ(既読状況・未読リマインド、0.3.0 から)

ログイン欄の下のタブ「送ったお知らせ」で使います(「お知らせを送る」タブに戻ると、書きかけの内容はそのまま残っています)。

- 「読み込む」を押すと、ログインしている社の `announcements` から、このツールで一括送信したもの(ID が `bc-` で始まるもの)を読み、新しい順に30件まで出します(ID の新しい順に絞り込む読み方はエミュレーターが対応していないため、`bc-` のものは全部読んで手元で並べる。一括送信が数百件を超えたら読み方を見直す)。同じIDは1行にまとめ、どの社にあるかが色の札で出ます。押すまでは何も読みません(自動で読み直すこともしません)
- 行を押すと、社ごとの既読状況が並びます。数え方は各社アプリの「到達率」と同じです
  - 対象 = `users` で `role` が `driver` の人
  - 既読 = その人の `announcements/{ID}/reads/{コード}` がある(割合は四捨五入)
  - 必読のときは「確認済み」(既読のうち、確認ボタンを押した人)の数も出ます。確認済みも、既読・未読と同じく対象(乗務員)に絞って数えます。各社アプリの CSV の「確認済み」は乗務員以外(管理者など)が確認した分も数えるので、数が合わないことがあります
  - まだ読んでいない人の名前とコードが並び、読んだ人の一覧は畳んであります
  - その社に無いお知らせは「この社にはありません」、ログインしていない社は「未ログインのため読めません」と出ます
- 最新にするときは「読み直す」を押します
- **未読リマインド**: 社ごとに「この社の未読の人にリマインドを送る」にチェックを入れ、「リマインドの確認へ」→ 確認画面 →「送信する」
  - 未読が0人の社は選べません
  - 確認画面には、社ごとの未読の人数、ロック画面に出る文言(`🔔 未読リマインダー` / `未読のお知らせがあります`)、通知の対象の概算人数、現在時刻が出ます。**送信後は取り消せません**
  - 送るのは各社アプリの「リマインド」と同じ処理(各社の `sendUnreadReminder`)で、社ごとに順番に送り、1社が失敗しても他社は止めません。結果に社ごとの未読の人数と通知を届けた件数が出ます
  - 必読で「読んだが確認ボタンを押していない」人は、リマインドの対象外です(未読の人だけに届く。アプリと同じ)
  - 送ったあとはボタンが押せなくなります。もう一度送るには「読み直す」を押します
  - 送った時刻はお知らせ・社ごとに記録し、「HI-LINE は ◯分前(日時)に送りました」と出ます。選んだ社のうち、そのお知らせのリマインドを前に送った社があると、確認画面に警告が出て、もう一度送ることの確認(チェック)をしないと送れません。記録はこのブラウザにだけ残ります(別のPC・別のブラウザで送った分は出ません)

### 7. 訂正・削除(0.4.0 から)

「送ったお知らせ」で1件を開き、下の「✏️ 訂正・削除」から使います。

- **訂正する**
  - 直せるのは、タイトル・本文・カテゴリ・優先度・上部に固定・既読期限・タグだけです。必読の ON/OFF・投稿者・対象・状態は変わりません
  - 入力欄は、訂正できる社のうち最初の社の今の内容から始まります。社によって今の内容が違う項目があると、表で並びます(訂正すると、選んだ社はすべて入力欄の内容になります)
  - 訂正する社を選びます(訂正できる社は最初から選ばれています)。**必読で、まだ通知が送られていない社(`notifiedAt` が無い)は選べません**(訂正した瞬間に全員へ通知が飛ぶため。理由が出ます)
  - 確認画面に、社ごとの「訂正前 → 訂正後」が出ます。変更が無い社には書き込みません
  - 書き込む直前に各社の今の内容を読み直し、読み込んだあとに内容が変わっていた社(アプリで直された・通知の状態が変わった など)は、書き込まずに止めます。「読み直す」を押してからやり直してください
  - **訂正しても、もう読んだ人には知らせが行かず、新着にもなりません。プッシュ通知も飛びません。** 大事な訂正は新しいお知らせで出してください
- **削除する**
  - 削除する社を選びます(最初はどれも選ばれていません)。確認画面に、社ごとのタイトル・必読・既読の人数が出ます。**削除すると取り消せません**
  - 各社アプリの削除と同じく、お知らせ本体だけを消します。既読の記録(`reads`)は残ります。通知は飛びません
- どちらも社ごとに順番に書き込み、1社が失敗しても他社は止めません。書き込んだあとはボタンが押せなくなるので、続けるときは「読み直す」を押します

## 書き込む内容

各社アプリの `submitAnnPayload()` の「新規・即時公開」と同じ16項目だけを書きます(項目は増やさない)。

| 項目 | 値 |
|---|---|
| `title` / `body` | 前後の空白を除いた文字列(3社とも同じ) |
| `category` | `safety` / `work` / `hr` / `system` / `other` |
| `priority` | `high` / `normal` / `low` |
| `target` | `'all'` |
| `pinned` / `mustRead` | 真偽値 |
| `readDeadline` | `'YYYY-MM-DD HH:MM'` か `null` |
| `tags` | 文字列の配列(20文字以内・最大5個・重複なし・先頭の `#` を外す) |
| `status` | `'published'` |
| `scheduledAt` | `null` |
| `updatedAt` / `createdAt` / `publishedAt` | サーバー時刻 |
| `authorUid` | ログインしたコード |
| `authorName` | 投稿者名(空欄ならログインした人の `users.name`) |

- ドキュメントID は1回の一括送信につき1つ(例: `bc-20261017-2004-k3f9`)で、3社で同じIDを使います
- 書き込みは「無ければ作る」だけです。先にサーバーから読み、無いときだけトランザクションで作成します。既にあるドキュメントは上書きしません(上書きすると `notifiedAt` が消え、必読通知がもう一度全員に飛ぶため)
- 社ごとに順番に書き込み、1社が失敗しても他社は止めません

訂正(0.4.0 から)は、各社アプリの編集(`submitAnnPayload()` の `update`)のうち、次の8項目だけを `update` します(項目は増やさない。`notifiedAt` など、ほかの項目には触れない)。

| 項目 | 値 |
|---|---|
| `title` / `body` / `category` / `priority` / `pinned` / `readDeadline` / `tags` | 上の表と同じ決まり |
| `updatedAt` | サーバー時刻 |

- 書き込みはトランザクションで、中で「お知らせがある」「必読で `notifiedAt` が無い状態ではない」「読み込んだときから `updatedAt` が変わっていない」を確かめてから `update` します。どれかに当たったら例外で止め、何も確定させません(読んだだけで書かずに終わるトランザクションも、既存のドキュメントへの書き込みとして届き `onAnnouncementNotify` が動くため)
- 削除は、サーバーから読んで、あれば `delete` します。ID が一括送信の形(`bc-` で始まる)でなければ、訂正も削除もしません

## 通知について

- 必読ONのときのプッシュ通知は、各社のサーバー処理 `onAnnouncementNotify` がこれまでどおり送ります。投稿のときにツールから通知は送りません
- 必読OFFでもプッシュ通知は飛びませんが、ベル・タブの赤い点は全員に付きます
- 未読リマインド(0.3.0 から)は、ツールが各社の `sendUnreadReminder` を呼び、各社のサーバー処理が未読の人に通知を送ります(未読の人のうち、通知を許可していて端末を登録している人にだけ届く)
- 訂正・削除(0.4.0 から)では通知は飛びません。ただし `onAnnouncementNotify` は更新でも動き、「公開済み × 必読 × `notifiedAt` が無い」と全員に通知を送るため、その状態の社は訂正しません

## 申し送り

### 各社アプリ側を変えたとき

このツールは、各社アプリの次の部分を写して作っています。アプリ側を変えたら、ツールも合わせて直してください(ツール本体 `index.html` の該当箇所にもコメントがあります)。

- 各社 `index.html` 冒頭の `firebaseConfig`(→ `COMPANIES`)。projectId・authDomain・Functions のリージョンを変えたら、ツール本体 `index.html` の `<head>` にある Content-Security-Policy の宛先(`connect-src`・`frame-src`)も直す
- ログイン方式 `AUTH_EMAIL_DOMAIN` / `AUTH_PW_SUFFIX`
- エディタのカテゴリ(`annCategories`)・優先度・既定値・タグの正規化(`addEdTagFromInput()`)
- 投稿の項目(`saveAnn()` / `submitAnnPayload()` → `PAYLOAD_KEYS`・`buildPayload()`・`checkPayload()`)
- `announcements` のルール、`onAnnouncementNotify`(タイトルを60文字で切る)、`firebase-messaging-sw.js` の通知文言、`estimateNotifyAudience` の呼び方
- 動いてよい場所はツール本体 `index.html` の `judgePlace()`(`LOCAL_PORT`・`PAGES_HOST`・`PAGES_PATH`)で決めている。リポジトリ名・GitHub のアカウント名・`serve.js` のポートを変えたら、ここも直す
- 既読状況の数え方(`fetchAnnAllDrivers()` / `buildAnnReadStatus()` → ツールの `loadDetail()`・`buildReadStatus()`)。アプリの CSV の「確認済み」は乗務員以外の reads も数えるが、ツールは対象(乗務員)のうちの確認済みだけを数える
- 未読リマインド(`sendReminder()` → callable `sendUnreadReminder`、`estimateNotifyAudience` の `eventKey: 'unreadReminder'`、`firebase-messaging-sw.js` の `unreadReminder` の文言)。callable の名前・引数・戻り値(`unreadCount` / `sent`)を変えたら、ツールの `onRemindSend()` も直す
- 訂正・削除(`saveAnn()` の編集 / `submitAnnPayload()` の `update`、`confirmDeleteAnn()` → ツールの `EDIT_KEYS`・`checkEditPayload()`・`updateOne()`・`deleteOne()`)。`onAnnouncementNotify` の送る条件(公開済み × 必読 × `notifiedAt` が無い)を変えたら、ツールの `wouldNotify()` も直す
- `COMPANIES` の `rendersHtml` は、お知らせを HTML のまま表示する社を `< > &` を含む投稿の送信先から外す仕組み。いまは3社とも `false`(HI-LINE は 0.4.9 で解除)。各社アプリでお知らせの表示を変えるときは、文字として表示する作り(`escHtml()`)を崩さないこと。崩れた社が出たら、その社を `true` にする

### 検証について

- CSP を絞ったあとのエミュレーターでの送信は、2026-10-19(0.2.1)に確認済み。3社にログインし、必読ONで確認画面(人数の概算)から送信まで通り、3社とも同じIDの投稿(17項目、`notifiedAt` あり)ができ、`onAnnouncementNotify` の送信判定は各社1回だった
- 次にエミュレーターで検証するときも、まずログインと書き込みが通るかを確かめる
- 0.3.0(送ったお知らせ・未読リマインド)は 2026-10-20 にエミュレーターで確認済み。3社に必読で一括送信し、乗務員・管理者として既読・確認を付けたうえで、ツールの数字(対象・既読・割合・確認済み・未読者)が3社とも各社アプリの写しの `fetchAnnReadStatus()` と一致した(確認済みは、アプリの CSV が管理者の確認も数えて 2、ツールは乗務員だけで 1)。リマインドは、キャンセルでは何も呼ばれず、送ると各社の `sendUnreadReminder` が1回ずつ送信まで進み(ボタンの2度押しでも1回)、1社を送信直前にログアウトさせても他社は送られた。未読0の社は選べず、未ログインの社・お知らせが無い社はその旨が出た。トークンは最初から最後まで0件
- 0.4.0(訂正・削除)は 2026-10-21 にエミュレーターで確認済み。訂正では、直した項目と `updatedAt` だけが変わり、ほかの項目と `notifiedAt` は変わらなかった(項目数も同じ)。訂正のあと `onAnnouncementNotify` は動いたが送信までは進まなかった。`notifiedAt` の無い必読の社は選べず、確認画面を開いたあとに `notifiedAt` を消した社・`updatedAt` が変わった社は、書き込まずに止まった(このとき `onAnnouncementNotify` も動かなかった)。ボタンの2度押しでも書き込みは各社1回。削除では、選んだ社の本体だけが消え、`reads` は残り、ほかの社は変わらなかった。トークンは最初から最後まで0件
- エミュレーターは、ドキュメントID の降順の範囲指定(`orderBy(documentId, 'desc')`)に対応していない。ツールは昇順で読んで手元で並べている
- `inspect.js fnlog` の「送信まで進んだ回数」は関数ごとに数える。callable はブラウザの事前確認でも開始・終了の行が出るので、開始の行の数は実行回数の2倍になる

## エミュレーターでの確認(本番には触れない)

アプリやツールを変えたときに、3社のエミュレーター(各社の `firestore.rules` と `functions` を読み込む)で確かめるための道具が `emulator/` にあります。作業用のファイルは Google ドライブの外(既定: `%LOCALAPPDATA%\matomete-broadcast-emu`)に作ります。

```
node emulator/prepare.js --repos <3社のリポジトリを並べたフォルダ>   (初回・各社を更新したとき)
node emulator/start.js                                                (3社のエミュレーターを起動。別の画面で動かしたままにする)
node emulator/seed.js                                                 (検証用アカウントを作り直す)
node serve.js                                                         (ツールの簡易サーバー)
```

- ツールは `http://localhost:8765/?emulator=1` で開くとエミュレーターに接続します(画面上部にオレンジの帯が出る)
- 各社アプリの写し(エミュレーター接続版)は `http://localhost:8766/hiline/index.html`(`alogi` / `meiho` も同様)。比較用の投稿をアプリから作れます
- 検証用アカウント(コード・パスワード)は `emulator/config.js` の `TEST_USERS`。エミュレーターの中にだけあり、本番とは無関係です
- 中身の確認: `node emulator/inspect.js list`(一覧)/ `compare <key> <idA> <idB>`(項目名・型の比較)/ `fnlog`(`onAnnouncementNotify` の実行回数と、`sendUnreadReminder` が送信まで進んだ回数)/ `tokens`
- 確認画面の人数を見るときは `node emulator/seed.js --tokens` で架空の通知トークンを入れる。**必読の送信を試す前に必ず `--clear-tokens` で消す**(トークンがあると functions が本物の FCM に送ろうとするため)

## ファイル

| ファイル | 内容 |
|---|---|
| `index.html` | ツール本体(1枚)。0.1.0 までは `broadcast.html` という名前だった |
| `.nojekyll` | GitHub Pages にファイルをそのまま配らせるための空ファイル |
| `serve.js` | マイPCの中だけで開くための簡易サーバー(依存パッケージなし) |
| `start-broadcast.bat` | マイPCでの起動用(`serve.js` を起動してブラウザを開く) |
| `emulator/` | エミュレーターでの確認用の道具 |

このリポジトリは public で、GitHub Pages は `main` のルートをそのまま配ります。`README.md`・`emulator/` なども公開URLの下から読めます。パスワードや鍵はコミットしないこと(`emulator/config.js` のパスワードはエミュレーター専用の架空のもの)。

外部から読み込むのは gstatic の Firebase JS SDK(compat 10.14.1。各社アプリと同じ版)だけです。内容が書き換えられていたら読み込まないよう integrity を付けています。

通信できる宛先は、SDK のコードで確かめた次のものだけに絞っています(ツール本体 `index.html` の Content-Security-Policy)。

| 宛先 | 用途 |
|---|---|
| `identitytoolkit.googleapis.com` | ログイン |
| `securetoken.googleapis.com` | ログインの更新 |
| `firestore.googleapis.com` | Firestore の読み書き |
| `asia-northeast1-anzen-matomete-app.cloudfunctions.net` ほか2社分 | 人数の概算(`estimateNotifyAudience`)・未読リマインド(`sendUnreadReminder`) |
| `127.0.0.1` / `localhost` | 検証用のエミュレーター(エミュレーター接続は `localhost:8765` で開いたときだけ有効) |

公開URLで使うときの注意:

- 公開URLは各社アプリ(`/matomete-app/` など)と同じ `https://hanyama54321-cyber.github.io` のサイトにあり、ブラウザの保存領域を共有します。ツールのログイン情報はタブ単位で保存し、保存名(`firebase:authUser:…:hiline` など)と記憶するコードの名前(`matomete-broadcast:` で始まる)は各社アプリと重なりません。使い終わったらタブを閉じてください
- GitHub Pages では「ほかのページへの埋め込み禁止」をヘッダーで指定できないため、ツールが埋め込まれたことを自分で調べて締め出します
